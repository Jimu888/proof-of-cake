# Mement 平台流程演示

2026-11-09。延续黑金精品陈列，当前完成本地可运行的精选作品 → 作品详情 → 填写收礼人和公开祝福 → 核对 → 保存预览 → 打开礼盒 → 欣赏作品和信件。

## 入口

- 首页 `/`，三件概念作品，来自统一目录 `src/domain/catalog.ts`。
- 作品详情及送礼 `/gifts/cat`、`/gifts/sheep`、`/gifts/flower`。
- 收礼 `/gift/{随机令牌}`，由演示订单生成，刷新或重启服务后可恢复，有效期七天。
- `/receive` 和《计划之外》个例交付继续具有原有入口与发布版本。平台流程不会将该个例当作可再次售卖的商品。

## 演示与正式系统

作品、创作者署名、版数、价格及发行规则为明确标识的示例。模型作品和视频媒介尚未接入统一平台收礼页。暂未接入网站钱包认证、实际域名解析、真实支付、通用 NFT 购买合约、主网交易确认与分账。

收礼预览直接显示祝福、赠送人示例和时间，展开作品信息可查看发行规则。没有伪造钱包身份、到账状态或交易哈希。只保存演示输入，请使用示例名字、地址和公开文字。

## 存储与边界

Node.js 24 内置 SQLite 保存本地演示订单，文件 `delivery/platform-demo/orders.sqlite` 已被 Git 忽略。它需要可写本地磁盘，不适用于当前静态 Cloudflare Pages，也不是生产数据库迁移方案。有效记录上限一千；过期清理后，旧幂等键不再保留。

服务端生成价格、发行版本与规则、分成快照。分成不发送到浏览器，前端无法提交价格或自定规则。金额使用最小单位十进制字符串。相同幂等键和内容返回原订单，冲突拒绝，保存由 SQLite 事务保护。公开令牌随机生成，不提供列出订单的接口。错误、失效链接、网络重试和复制失败有展示反馈。

正式系统仍需 PostgreSQL、身份验证、基于用户的幂等键、链上库存与订单校验、接口限流、报价有效期、交易事件核验及重组恢复。该演示服务仅供本机查看，不应直接公开上线。

## 创作者申请与人工审核

2026-11-09 新增 `/creators/apply`，顶部导航及页脚可进入，手机顶部也保留入口。表单填写署名、联系方式、作品集链接、媒介及创作计划，提交为待审核。申请信息不要求钱包登录，也不证明作者身份或作品授权。

POST `/api/demo/creator-applications` 接收表单并以 Idempotency-Key 防重。仅本地保存，未接通知或正式入驻流程。`delivery/platform-demo/applications.sqlite` 是独立私有审核列表，不进入作品目录或公开接口。

人工审核使用本地命令。`npm run creators -- list` 查看列表；`npm run creators -- review <申请编号> approved` 或 `rejected` 记录通过/拒绝。此命令输出包含联系方式，应由运营本地查看。审核通过不会自动发信、创建创作者账号或发行作品。公开上线前需接入持久数据库、受保护的运营后台、限流与通知。

## 钱包登录与 BSC 测试网

从首页「钱包登录」进入 `/wallet`。浏览器插件和钱包 App 内置浏览器通过 EIP-1193 接入，支持 EIP-6963 多插件发现。钱包需支持 BSC 测试网。登录使用服务器生成的 EIP-4361 消息，验证普通地址签名。挑战绑定站点与浏览器且五分钟失效，成功后消耗。登录会话保存在本地服务进程，使用 HttpOnly Cookie，重启后重新登录。

测试网络固定为链 ID 97，平台展示由节点返回的区块高度。WalletConnect 二维码需要配置 `WALLETCONNECT_PROJECT_ID`。钱包 App 在同一部手机上可通过内置浏览器打开可达的站点。远程测试需填写与浏览器一致的 `MEMENT_ORIGIN`。

测试赠礼合约位于 `contracts/platform/MementTestGift.sol`。使用 Node 24 运行 `node scripts/testnet-deployment.mjs <部署钱包> <创作者钱包> <平台钱包>` 生成未签名部署参数。部署钱包需要 tBNB。合约固定测试价格 0.0001 tBNB、30 份、50/50 分成、不可转让、持有人可销毁。分成在购买时记入双方可提余额，由各自钱包提取。部署确认后将测试网地址填入 `MEMENT_TESTNET_CONTRACT`，重启网站。收礼地址以完整 EVM 地址输入。核验检查指定合约的购买和铸造事件，等到三次确认后显示代币编号。

## 测试网发行验收

1. 打开本地运营后台 `/ops`，使用本机运营密钥登录。审核示例作者，生成上传凭证。
2. 打开 `/creators/studio`，提交静态图片和封面，填写售价、版数与授权。回到后台批准陈列。
3. 在作品下点击「测试网发行」。连接有 tBNB 的钱包，填入两个由测试方控制的不同收款地址。在钱包确认部署，等待三次确认，再点「核验并绑定测试版」。保留部署交易哈希，刷新后可重新填入核验。
4. 从作品详情点击「测试网购买赠礼」。连接有 tBNB 的买方钱包，填写收礼地址与公开祝福，核对地址并确认付款。刷新后，同一浏览器标签可恢复交易哈希并重新核验。
5. 打开收礼页，核对作品与祝福。运营后台的销售页应出现对应作品、金额和分成。重复核验同一交易后，成交件数应保持不变。

本轮验收使用隔离的本地链 97 和模拟浏览器钱包。公网 BSC 测试网部署、钱包插件实测和手机扫码仍待进行。下架停止平台陈列和购买入口，已部署的合约仍可直接调用。当前发行版价格固定，改价需要新版本。销售记录在收礼页或交易核验时入账，链外付款可通过后台导入哈希补录。后续待接自动扫描、提款对账、作者审核意见及正式生产权限。
